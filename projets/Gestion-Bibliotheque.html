INTRODUCTION

Introduction

La gestion d'une bibliothèque nécessite aujourd'hui des outils efficaces permettant de centraliser les informations, d'automatiser les procédures et de faciliter l'accès aux ressources. Dans de nombreuses structures, les opérations telles que l'enregistrement des livres, la gestion des emprunts, le suivi des réservations ou encore l'administration des utilisateurs sont souvent réalisées manuellement ou à l'aide d'outils peu adaptés. Cette organisation entraîne des pertes de temps, des erreurs fréquentes et une difficulté à produire des statistiques fiables.

Face à ces limites, il devient indispensable de mettre en place une application informatique moderne pour optimiser le fonctionnement global de la bibliothèque. Le présent projet vise donc à concevoir et développer une solution simple, intuitive et sécurisée permettant de gérer efficacement les différentes activités du système.

L'objectif principal de l'application est de faciliter la gestion des livres et des adhérents, tout en automatisant les processus d'emprunt et de réservation. Plus spécifiquement, le système permettra :

  • L'enregistrement, la classification et la mise à jour des livres ;
  • La gestion des adhérents et de leurs informations ;
  • Le suivi des emprunts, retours et retards éventuels ;
  • La gestion des réservations de livres ;
  • La consultation rapide et fiable des données stockées.

Pour mener à bien ce projet, une démarche rigoureuse a été adoptée. La méthodologie MERISE a été utilisée pour l'analyse et la conception du système à travers le dictionnaire des données, le Modèle Conceptuel de Données (MCD) et le Modèle Logique de Données (MLD). La phase de développement a été réalisée en utilisant PHP pour la partie applicative et MySQL pour la création et la gestion de la base de données. Cette combinaison technologique garantit une application dynamique, évolutive et compatible avec un déploiement sur serveur web.

Ce rapport présente l'ensemble du processus de conception et de réalisation de l'application de gestion de bibliothèque, depuis l'analyse des besoins jusqu'au développement des premières interfaces fonctionnelles.

SECTION I

Cahier des charges

1 Contexte

La bibliothèque souhaite automatiser la gestion de son catalogue (livres, auteurs, catégories), la gestion des adhérents, et les opérations d'emprunt, retour et réservation. L'objectif est de gagner en efficacité, réduire les erreurs manuelles et obtenir des rapports fiables.

2 Objectifs

  • Fournir une application web (PHP + MySQL) simple, sécurisée et maintenable.
  • Permettre la gestion CRUD des livres, auteurs, catégories et adhérents.
  • Gérer les emprunts, retours, pénalités et réservations.
  • Assurer un contrôle d'accès (rôles : admin / bibliothécaire / adhérent).
  • Produire des rapports simples (emprunts en cours, retards, top livres).

3 Utilisateurs

  • Admin : gestion complète, création comptes, maintenance.
  • Bibliothécaire : gestion quotidienne (livres, adhérents, emprunts/retours, réservations).
  • Adhérent : consultation du catalogue, consulter ses emprunts, réserver.

4 Périmètre fonctionnel

  • Gestion des livres (titre, auteur, catégorie, isbn, nb_exemplaires, nb_disponible).
  • Gestion des auteurs & catégories.
  • Gestion des adhérents (nom, email, téléphone, rôle, mot de passe, photo).
  • Emprunt : vérifier disponibilité, limiter à 5 emprunts simultanés, durée par défaut 14 jours.
  • Retour : enregistrement de la date de retour, calcul de pénalité si retard (ex : 200 F/jour).
  • Réservation : file d'attente FIFO ; notification (simulé) lorsque disponible.
  • Authentification (login/logout), pages protégées selon rôle.

5 Contraintes & règles de gestion

  • Durée emprunt par défaut : 14 jours (configurable).
  • Max emprunts simultanés par adhérent : 5.
  • Lorsque nb_disponible = 0, l'adhérent peut réserver.
  • Lors du retour, si une réservation existe → statut réservation passe à notifiée/attribuée.
  • Historique des emprunts conservés.

6 Livrables

  • Code source PHP (dossier projet), fichier SQL de la BD, rapport imprimé (10–15 pages), captures écran.
  • Date de rendu : 12/12/2025.

SECTION III

Base de données

1 Création de la base et des tables

SQL
-- Création base DROP DATABASE IF EXISTS bibliotheque; CREATE DATABASE bibliotheque CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci; USE bibliotheque; -- Table AUTEUR CREATE TABLE auteur ( id_auteur INT NOT NULL AUTO_INCREMENT, nom VARCHAR(100) NOT NULL, prenom VARCHAR(100) DEFAULT NULL, bio TEXT, PRIMARY KEY (id_auteur) ); -- Table CATEGORIE CREATE TABLE categorie ( id_categorie INT NOT NULL AUTO_INCREMENT, libelle VARCHAR(100) NOT NULL, PRIMARY KEY (id_categorie), UNIQUE KEY libelle (libelle) ); -- Table LIVRE CREATE TABLE livre ( id_livre INT NOT NULL AUTO_INCREMENT, isbn VARCHAR(20) NOT NULL, titre VARCHAR(255) NOT NULL, annee_pub YEAR DEFAULT NULL, nb_exemplaires INT NOT NULL DEFAULT 1, nb_disponible INT NOT NULL DEFAULT 1, resume TEXT, id_categorie INT DEFAULT NULL, PRIMARY KEY (id_livre), UNIQUE KEY isbn (isbn), KEY id_categorie (id_categorie) ); -- Table ADHERENT CREATE TABLE adherent ( id_adherent INT NOT NULL AUTO_INCREMENT, nom VARCHAR(100) NOT NULL, prenom VARCHAR(100) NOT NULL, email VARCHAR(150) NOT NULL, telephone VARCHAR(20) DEFAULT NULL, date_inscription DATE NOT NULL DEFAULT (CURDATE()), role ENUM('adherent','bibliothecaire','admin') NOT NULL DEFAULT 'adherent', mot_de_passe VARCHAR(255) NOT NULL, photo VARCHAR(255) DEFAULT NULL, PRIMARY KEY (id_adherent), UNIQUE KEY email (email) ); -- Table ECRIRE (relation N:N) CREATE TABLE ecrire ( id_auteur INT NOT NULL, id_livre INT NOT NULL, PRIMARY KEY (id_auteur, id_livre), KEY id_livre (id_livre) ); -- Table EMPRUNT CREATE TABLE emprunt ( id_emprunt INT NOT NULL AUTO_INCREMENT, id_livre INT NOT NULL, id_adherent INT NOT NULL, date_emprunt DATE NOT NULL, date_retour_prevue DATE NOT NULL, date_retour_effective DATE DEFAULT NULL, statut ENUM('en_cours','rendu','retard') NOT NULL DEFAULT 'en_cours', penalite DECIMAL(7,2) DEFAULT 0.00, PRIMARY KEY (id_emprunt), KEY id_livre (id_livre), KEY id_adherent (id_adherent) ); -- Table RESERVATION CREATE TABLE reservation ( id_reservation INT NOT NULL AUTO_INCREMENT, id_livre INT NOT NULL, id_adherent INT NOT NULL, date_reservation DATETIME NOT NULL, statut ENUM('en_attente','annulee','notifiee','attribuee') NOT NULL DEFAULT 'en_attente', PRIMARY KEY (id_reservation), KEY id_livre (id_livre), KEY id_adherent (id_adherent) );

2 Interfaces utilisateur

L'interface utilisateur constitue un élément central de l'application. Elle permet aux différents acteurs d'interagir avec le système de manière simple et intuitive. Le design repose sur Bootstrap et du CSS personnalisé afin d'assurer une expérience fluide, responsive et adaptée à tous les supports.

A. Page d'accueil (index.php)

Page d'accueil avec design immersif et présentation des services

La page d'accueil constitue le point d'entrée principal de l'application. Elle présente un design immersif avec une image de fond représentant une bibliothèque universitaire prestigieuse. Le slogan central "Découvrez le Savoir Infini" invite les visiteurs à explorer les ressources disponibles. Deux boutons d'action : Se connecter et Créer un compte. Une section "Pourquoi Choisir Notre Bibliothèque ?" met en avant les avantages du service.

B. Page de connexion (login.php)

Formulaire de connexion sécurisé

La page de connexion permet aux utilisateurs enregistrés d'accéder à leur espace personnel. Formulaire avec champs email et mot de passe, lien vers l'inscription. Arrière-plan représentant une bibliothèque classique aux boiseries sombres.

C. Page d'inscription (inscription.php)

Formulaire d'inscription d'un nouvel adhérent

Formulaire d'inscription complet avec champs : nom, prénom, email, téléphone, mot de passe, photo (optionnelle). Arrière-plan studieux évoquant la recherche et le savoir.

D. Tableau de bord – Adhérent

Tableau de bord personnel de l'adhérent

Le tableau de bord de l'adhérent constitue son espace personnel après connexion. Il offre une vue synthétique de son activité au sein de la bibliothèque et facilite la navigation vers les fonctionnalités clés. Quatre indicateurs statistiques présentent :

  • Nombre total d'emprunts en cours
  • Nombre de réservations actives
  • Livres disponibles
  • Pénalités éventuelles

Des sections dédiées permettent d'accéder rapidement au catalogue, à l'historique des emprunts et aux réservations personnelles.
